**Agent file format:**
- YAML frontmatter with required `name` and `description`, plus `tools`, `model`, `color`
- Opening `<!-- WHY THIS AGENT EXISTS: ... -->` comment explaining the agent pattern being taught
- Markdown body IS the system prompt — instructions for how the agent should behave

**1. lah-code-reviewer.md** — Read-only analysis agent
- `tools: Read, Grep, Glob` (NO Edit, NO Write, NO Bash — read-only pattern)
- `model: sonnet` (fast, cost-effective for reviews)
- `color: teal`
- Description triggers: "review this", "check my code", "what do you think"
- System prompt teaches: read the diff/file, focus on modified code, review checklist (logic errors, security, error handling, performance, types), output as Critical/Warning/Suggestion with exact fixes
- Pedagogical comment explains: restricted tools = safety (can't accidentally modify code during review)
- 40-60 lines total

**2. lah-planner.md** — Plan-mode agent (strategic, no writes)
- `tools: Read, Grep, Glob, Bash` (Bash for `git log`, `ls`, etc. — but NO Edit/Write)
- `model: opus` (best reasoning for planning)
- `color: purple`
- Description triggers: "plan this feature", "how should I architect", "break this down"
- System prompt teaches: understand the codebase first (read relevant files), state the goal, list unknowns, propose 2-4 implementation steps, identify risks, suggest which step to start with
- Pedagogical comment explains: opus model = stronger reasoning for architectural decisions; no write tools = planning stays separate from implementation
- 40-60 lines total

**3. lah-debugger.md** — Full-access fix agent
- `tools: Read, Edit, Bash, Grep, Glob, Write` (full access — this agent can fix things)
- `model: inherit` (uses whatever model the user has selected)
- `color: orange`
- Description triggers: "debug this", "fix this bug", "why is this failing"
- System prompt teaches: scientific debugging method — reproduce, hypothesize, add one diagnostic, verify, fix. Never guess. Always confirm the fix resolves the original issue. Run tests after fixing.
- Pedagogical comment explains: full tool access = the agent can both diagnose AND fix; `inherit` model = uses the user's current model choice; this is the "trust the agent" pattern
- 40-60 lines total

**4. lah-explainer.md** — Minimal-tool knowledge agent
- `tools: Read` (absolute minimum — can only read files)
- `model: haiku` (fastest, cheapest — explanation doesn't need deep reasoning)
- `color: blue`
- Description triggers: "explain this", "what does this do", "how does this work", "teach me"
- System prompt teaches: explain code using analogies, ASCII diagrams, step-by-step traces. Layer from simple to complex. Always start with the "elevator pitch" (one sentence), then go deeper.
- Pedagogical comment explains: haiku = fast and cheap for knowledge work; Read-only = the safest possible agent; demonstrates the "minimal privilege" pattern
- 40-60 lines total
